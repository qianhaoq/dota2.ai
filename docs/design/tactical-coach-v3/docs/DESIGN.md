# 全站产品、交互与视觉重设计

## 1. 产品定义

教玩家做判断，不替玩家玩游戏。玩家需要三个答案：眼前是什么局面；有哪些选择及代价；下一局能练什么。承诺“判断更清楚”，不承诺上分、胜率增益、完美出装或精确胜负预测。

核心循环：**局面 → 判断 → 可操作推演 → 玩家补充/选择 → 教练修正 → 下局练习 → 下一次检查**。

聊天承载问题，地图承载空间，英雄承载视角与目标，装备承载取舍，时间线承载证据，训练承载判断。不是把所有东西都输出成 Markdown，也不把所有问题强行变成地图。

三种教练方式：“直接给要点”“一起拆解”“让我先判断”。赶时间时不强迫做选择题。原型重点演示后两种；生产版共用同一会话。

默认拉比克是表达层，不是事实来源。更换导师不重跑分析、不变更比赛英雄、不提高可信度。默认可直接开始，不以选择导师为入场关卡。

## 2. 信息架构与稳定工作区

一级导航只有：**战术室 / 英雄修炼 / 英雄图鉴 / 战术笔记**。

战术室内包括首次进入、赛后复盘、战前阵容、装备取舍。BP、出装、思路、版本和百科不再全部并列成首页按钮墙。

桌面：顶部稳定导航；上下文条明确比赛/视角/状态；左侧教练一句要点和本次目标；中央主要交互；证据/资料抽屉按需打开；底部围绕当前场景追问。不是常驻四列看板。

移动：底部四个带文字的入口；教练压缩为一行；一次聚焦一个决策；地图提供局部视图与文字替代；证据为全屏抽屉。保留 safe-area、visualViewport、草稿、焦点与返回位置，不直接缩小桌面三栏。

会话区分 mentorId、practiceHeroId、focusPlayerSlot、mySide、editingSide/Slot。比赛视角以实际玩家槽位为主键，heroId 为描述，避免特殊模式/重复英雄混淆。当前 API 只接受 heroId 的限制由适配层明确校验。

## 3. 七个工作区

### 3.1 战术室入口

主标题“把下一次判断，练得更好”。动机入口：刚打完、准备开局、想练一下。每个状态只有一个视觉主操作；未连接账户不能伪造最近比赛、段位或成长分。

支持比赛 ID、受支持链接和自然语言。格式校验不等于读取成功；不自动读剪贴板。演示入口明确标记教学场景，不能关联真实 matchId。

真实导入：输入 → 只读拉取事实 → 实际参赛名单 → 选择自己的视角 → 显式开始分析。恢复任务不自动重新计费。账户关联和跨端历史同步属于后续能力，不画成已可用动作。

### 3.2 赛后复盘

首屏突出一个值得检查的决定，最多三个关键节点。KDA/GPM/XPM/伤害排行退到证据层，不作为视觉主角。

每个节点回答：当时已知什么；不知道什么；哪些选择及代价；建议在什么条件下成立。不用最终结果或全知视角责怪玩家当时没有掌握的信息。

点英雄只查看该对象的威胁/配合，不偷偷改“我是谁”。显式切换复盘玩家才创建新视角。点关键节点更新同一画布，保留其他结论；点依据打开事实字段；用户说“看见了”记为个人回忆，不自动制造坐标；“假设等队友先手”新建独立假设，不覆盖事实。

地图分三级能力：有校验的坐标与视野才能显示真实位置；只有分路推断用关系图/分路示意；只有统计与目标事件用非空间时间线。教学图可以开启，但必须与真实回放区分。原型地图仅为教学图。

结束时保存一条“触发情境 + 行为 + 检查方法”，不默认保存一串空泛建议，不把点击完成解释为进步。

### 3.3 战前阵容

从已知英雄开始，不要求选满。固定十格，支持预览、选中格、替换、逐格移除、撤销。格号只表示录入位置，不自动等同 1–5 号位。mySide 与 editingSide 独立。

教练先澄清玩家任务、常玩英雄与复杂度偏好，再比较最多三名候选。候选先显示“解决什么 / 与谁配合 / 代价 / 待确认条件”，样本退入证据层。样本胜率不叫本局获胜概率。

预览不改变阵容，点击采用才应用。只刷新受影响的配合/威胁/出装建议；没有结构化候选时只展示可用的澄清/文字，不造分数。

阵容变化递增 contextRevision，旧分析显示基于旧阵容。撤销只恢复阵容，不删除复盘或笔记；恢复后仍需核对快照。选满一侧不能静默往对方追加。

### 3.4 装备取舍

不是六格神装和长文。先明确眼前威胁、下一次目标与资源，再比较两条路线：用途、前提、牺牲项、改选条件。数字只在预算、合成或属性确实决定选择时出现。

问“这件是否太晚”需要当前经济、已有物品、购买时刻和下次目标。缺数据就问，不能用终局物品伪造购买时间线；没有可靠补丁机制就不画技能范围或断言效果。

选择路线只是偏好；显式“加入计划”才保存。用户补充资源或装备仍为 user_report，未经核验不升级成事实。原型只比较生存/输出两个抽象分支，不冒充当前补丁的具体推荐。

### 3.5 英雄修炼

选择英雄/目标不自动生成或计费。流程：冻结情境 → 隐去结果 → 玩家选择/标记 → 提交 → 展开条件与代价 → 换变体 → 保存动作。

反馈不是只有红错绿对。允许多个合理选择，检查“选择成立需要什么”；事实不足就不提供唯一最优路线。无真实 replay 数据的题目必须标为教学情境，不能冒充该玩家上一局的失误。

跨局验证需要角色、补丁与样本控制。人工检查标为自我报告；只有确有数据支持才标已观测。原型没有自动成长分。

### 3.6 图鉴、趋势与神秘商人

图鉴作为上下文资料层，保留中文/英文/别名搜索、完整英雄列表、技能、属性、背景与来源。新增情境入口不替代精确搜索。

技能先解释使用情境，再展开完整机制/数值。缺字段显示暂无资料，接口失败局部重试，不刷新整站。打开和关闭资料不卸载任务。设为练习英雄与预览加入阵容是两个明确动作。

版本趋势作为辅助证据/筛选：显示来源、样本、更新时间与补丁范围；接口不支持的筛选不伪装可用。神秘商人保留在背景页，官方内容和模型演绎分开标识，不占一级导航。

### 3.7 战术笔记

保存动作而非整份报告：来源、触发、行为、失败条件、检查方法、人工/自动状态。支持完成/撤回、移除/撤销、去重与导出。

明确本机存储边界，失败退为内存；导出由用户触发。真实账号、对话、个人回忆不默认公开或上传。共享前提供隐去账号名/ID；保存不等于训练授权。

## 4. 共同状态规则

| 状态 | 展示 | 动作 |
|---|---|---|
| empty / needs-input | 最少所需信息、演示出口 | 补充、跳过可选项 |
| loading-facts | 真实阶段，不造百分比 | 取消并保留输入 |
| facts-ready | 校验后的事实和名单 | 选视角、换比赛 |
| generating / partial | 已完成组件和事实 | 停止、写下一条草稿 |
| ready | 一条要点、交互对象、依据 | 比较、追问、保存 |
| needs-clarification | 一个关键问题 | 回答、记不清、有限分析 |
| cancelled / interrupted | 保留部分结果 | 重试同一任务 |
| error / unavailable | 局部失败和事实 | 局部重试 |
| stale | 原快照与变化原因 | 保留查看、显式重分析 |

生成中允许继续写，提交需明确等待/排队，禁止重复计费。停止立即解除忙碌并使旧 run 失效；导航不重跑生成；SSE 重连不重复应用版本。所有动作声明影响范围。

## 5. 视觉逻辑

深石板、铁灰、暗铜、灰金，余烬红只用于主操作。保留英雄本色，不把整站刷成荧光绿。Dota 元素进入可操作对象：天辉/夜魇、英雄阵列、河道、迷雾、装备、技能、关键节点、战术标记，而不是只贴壁纸。

正文无纹理干扰，稳定可读；标题可衬线，正文系统无衬线。事实用中性/冷蓝 + 来源；假设用灰金 + 虚线；危险用锈红 + 图形；未知用雾区 + 文字，不只靠颜色。无数据不能画貌似精确的位置。

每态一个视觉主操作。动词具体：比较另一种选择、查看依据、带进下一局。导师有存在感但不挤任务；不用持续粒子或闪烁扰动。

动效：选中 120ms，局部入场 160–220ms；不重排用户正在阅读的对象，尊重 reduced-motion。触控目标默认 44px；地图小标记另加热区。布局检查不等于读屏或真机认证。

## 6. 文案与验证

推荐：“先确认这个信息，再决定是否跟进。”“当时的视野尚未拿到。”“你的回忆已保留。”“假设队友能先手，这个方案才成立。”

禁用：必输/必胜、没有来源的胜率增益、侮辱玩家、虚构已学习玩家打法、把生成故事当官方事实。

生产保留中文默认和英文切换；当前独立原型仅中文，不声称双语已验收。

先验证玩家能否复述一次决策的条件和代价，再看能否执行一个动作。建议跟踪有效决策闭环、证据可追溯、无数据结论拦截、同类情境解释质量；不以聊天轮数或报告长度代表价值。这些是待验证的设计假设，不是已经完成的用户研究。
