# DOTA2.AI — 战术教练 V3

基线：`main @ 98b91e27e13118ede2a9be425bb3e730e397482e`。设计日期：2026-09-09。

不是 Dota 数据看板，也不是换了英雄头像的聊天框。是一个与玩家共同看清局面、比较选择、练习判断的战术教练。

## 交付范围

本目录是全站设计交付，不是已上线的生产重写。不修改 `src/`、`server.js`、AI 提供方、既有 API 协议、CI 或部署。

- `docs/DESIGN.md`：全站产品架构、七个工作区、主流程、视觉和文案。
- `docs/A2UI.md`：组件目录、局部更新、动作闭环、证据、安全与协议边界。
- `docs/MIGRATION.md`：原文件和接口映射、分期、验收、回滚。
- `docs/tokens.json`：建议视觉 token；不覆盖现有 k3 token。
- `prototype/`：无依赖可点击原型、精简内部运行时及测试。

## 运行

在本目录运行 `python3 -m http.server 4173`，打开 `http://localhost:4173/prototype/`。

核心测试：`node --test prototype/runtime.test.mjs`。

语法检查：`node --check prototype/app.mjs`。

仓库原型默认通过 Valve CDN 加载英雄图片；失败时保留可读名称。会话交付 ZIP 另有离线 `preview.html`、已认可概念图的裁剪素材、13 张页面截图和浏览器检查记录。不捆绑字体文件。

## 能力边界

原型包含战术室、复盘、阵容、装备、训练、图鉴与笔记；支持条件比较、证据抽屉、逐格选人/移除/撤销、训练先答后讲、本机笔记、草稿和取消守卫。

场景 `TF-01` 是教学情境，不是一场真实比赛。没有接入 AI、Steam、真实比赛、视频播放器、逐时刻坐标或视野、完整英雄资料、当前版本推荐。比赛输入只校验格式。自然语言跳转是固定演示规则，不是意图模型。训练不计真实段位，也不证明能力提升。

内部运行时使用可信组件、受控 patch 与动作闭环的 A2UI 思路，**不是官方 A2UI wire protocol 兼容实现**。生产协议适配须单独实现与验收。

先让一个真实复盘闭环成立，再扩展其他场景。A2UI 不是更多卡片，而是更适合当前问题的交互对象。
