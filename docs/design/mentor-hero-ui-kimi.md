## 0. 背景与设计目标

### 0.1 现状问题

当前教练页空状态（`WelcomeState.tsx`）是一个"通用 AI 聊天空状态"：闪光图标 + 一句问候 + 建议问题列表 + 输入框。问题：

1. **没有产品个性**——换成任何聊天产品都成立，与 Dota 2 无关；
2. **隐喻缺失**——产品愿景是"Dota 2 英雄是导师，用户是学生"，但首屏没有任何英雄在场；
3. **CTA 模糊**——输入框、建议问题、选英雄 chip 三者竞争注意力，学生不知道第一步该做什么；
4. **继续打磨通用空状态没有复利**——方向错误时，抛光等于浪费。

### 0.2 产品隐喻（权威愿景）

> **英雄 = 导师（Mentor / Instructor），用户 = 学生（Student）。**

用户不是"打开一个聊天机器人顺便问问 Dota"，而是"拜入某位英雄门下，系统学习怎么玩好他/她"。导师能力覆盖：

| 能力 | 说明 |
|------|------|
| 英雄教学 | 跟导师学玩这个英雄（技能、节奏、定位） |
| 英雄分析 | 导师剖析自己：强度、克制关系、版本地位 |
| AI 解说/分析 | 覆盖 BP（ban/pick）、对局、出装、思路/决策 |
| 复盘（Stretch） | VOD / Replay 回顾点评（**Later，不在本期**） |

### 0.3 设计目标

1. 首屏即"拜师"：空状态 = 选择导师英雄，而不是通用聊天问候；
2. 每个界面状态有且仅有一个 Primary CTA；
3. 导师人格贯穿全程：头像、语气、课程文案都来自所选英雄；
4. 视觉收敛为暗色单色体系，CTA 反白，杜绝荧光色。

### 0.4 硬约束（不可违反）

| 约束 | 说明 |
|------|------|
| 暗色单色 | 全站暗色单色；**禁止使用 lime `#D8FF3E`** 及任何高饱和荧光色 |
| Primary CTA 反白 | 主按钮 = 白底黑字：`bg #F5F5F5` / `text #0B0B0C` |
| 教练页无比赛轮播 | 不在 Coach 内放职业赛/公共比赛 carousel（`ProMatchStrip` 不进入 Coach） |
| 数据接地 | 仅使用 OpenDota 公共 API（经 `server.js` 代理）+ Valve CDN 图片；**不用灰色遮罩占位**；**不抓取 Dotabuff** |
| 中文优先 | 所有 UI 文案默认中文（zh），英文（en）为切换态；本文档中的文案表即字符串契约 |

## 1. 产品信息架构（IA）

### 1.1 IA 总览

```
AI 教练 (Coach Tab)
│
├── 第一层：选择导师英雄（Choose your mentor）
│     └── 导师网格：按 属性 / 定位 / 难度 筛选 + 搜索
│
└── 第二层：课程模式（Lesson Modes）——选定导师后进入
      ├── BP 课     学 ban/pick：几手拿、克制谁、被谁克制、搭配谁
      ├── 对局课    学实战：对线、节奏、团战定位、逆风处理
      ├── 出装课    学出装：核心装顺序、局势装、针对装
      ├── 思路课    学决策：什么时候做什么、决策树、大局观
      └── 复盘课    【占位 · Later】上传/粘贴 replay，导师点评
```

**核心规则**：先有导师，后有课程。未选导师时不存在"课程"，也不存在自由聊天入口——学生的第一步永远是拜师。

### 1.2 课程模式定义

| 模式 | zh 名称 | en 名称 | 学生问题示例 | 数据接地（OpenDota） |
|------|---------|---------|--------------|----------------------|
| BP | BP 课 | Draft Lesson | "我这英雄几手拿？怕什么？" | `/heroes/{id}/matchups`（克制/搭配）、`/api/meta/heroes`（版本强度） |
| 对局 | 对局课 | Match Lesson | "对线期怎么打？中期干嘛？" | `/heroes/{id}/matchups`、hero stats |
| 出装 | 出装课 | Item Lesson | "核心装顺序？对面多物理出什么？" | `/heroes/{id}/itemPopularity`、item constants |
| 思路 | 思路课 | Mindset Lesson | "什么时候该抱团什么时候带线？" | 导师人格 + 阵容上下文（轻数据） |
| 复盘 | 复盘课（占位） | Review Lesson (Soon) | "看看我这把输在哪" | Later：OpenDota match 解析；**P0/P1 不做** |

### 1.3 导师人格契约（设计层）

- 选定导师后，该英雄的 **立绘（Valve CDN 竖图）、icon、中文名、称号** 成为课程的视觉锚点；
- 后端 system prompt 按导师人格生成（如斧王 = 强硬直接、水晶室女 = 温和耐心）——本文档只定义 UI 契约：每条导师消息携带 `mentorId`，前端渲染导师头像与人格化署名；
- 导师不是皮肤：课程建议、追问 chips、空课程引导文案全部以导师第一人称书写（"跟斧王学，先学挨打"）。

### 1.4 与现有 Tab 的关系

- `AI 教练` Tab：按本文档重构为"导师制教学"；
- `英雄百科`（HeroHub）Tab：保留为资料查阅，不承担教学；从百科详情可"拜师"跳转到教练页并预选该导师（P1）；
- 现有 `DraftAssistant` 的阵容选择能力**降级为 BP 课的"课件"**：只在 BP 课内出现，不再是全局入口（见 §2 S2-BP）。

**复用与改造对照**：

| 现有组件 | 去向 |
|----------|------|
| `WelcomeState.tsx` | **废弃**，由 `MentorGate` 取代（不再做通用聊天空状态） |
| `HeroPickerOverlay.tsx` | 筛选/搜索逻辑抽入 `MentorFilterBar`；全屏 overlay 形态取消，选导师是页面不是弹层 |
| `DraftContextChip.tsx` / `DraftStrip.tsx` | 从全局入口降级为 BP 课课件 |
| `ChatMessage.tsx` | 改造为 `MentorMessage`（导师人格渲染） |
| `IntentChips.tsx` | 改造为 `LessonChips`（按课程出追问） |
| `ProMatchStrip.tsx` | **不得出现在 Coach**（硬约束） |

### 3.2 各状态 Primary CTA（每屏唯一）

| 状态 | Primary CTA | 样式 | 次级操作（降级样式） |
|------|-------------|------|----------------------|
| S0 拜师 | 点击导师卡 | 卡片 hover 反白描边 | "版本推荐导师"文本链 |
| S1 选课 | 点击课程卡 | 卡片（首卡可用反白强调，至多一张） | 换导师文本链；自由提问输入框（opacity 降级） |
| S2 上课 | 发送提问 | 反白圆形发送钮（`#F5F5F5`/`#0B0B0C`） | 追问 chips、换课/换导师文本链 |
| S3 流式 | 停止生成 | 反白按钮 | 无（其余禁用） |

规则：**任何一屏不得出现两个反白级按钮**；次级操作一律文本链或 ghost。

### 3.3 交互规则

1. **键盘**：`/` 聚焦输入框（保留现状）；`Esc` 在 S1 返回 S0；流式中 `Esc` = 停止。
2. **流式中断**：`停止` 立即 abort（沿用 `AbortController` 现状）；中断后消息保留已生成部分并标注"已停止"。
3. **换导师**：S2/S3 中点"换导师"需二次确认；确认后清空课程上下文与消息，**保留 BP 课件中的阵容草稿**；S3 中先 abort 再跳转。
4. **换课**：S2 内换课不清空消息，追加一条系统分隔（"—— 进入出装课 ——"）。
5. **错误态**：API 失败在消息流内展示一行错误 + `重试` 文本链；不弹 toast、不用遮罩。
6. **加载态**：导师网格用骨架屏（骨架 = 表面色 `#141416` 块 + 微光扫过，**非灰色遮罩**）；英雄图加载失败显示名字首字占位，不显示灰块。
7. **空数据**：OpenDota 无数据时渲染"暂无数据"文字行，不渲染占位卡片。

### 3.4 数据接地（OpenDota，经 `server.js` 代理）

| 用途 | 端点 | 现状 |
|------|------|------|
| 英雄列表/立绘/属性 | `/api/meta/heroes`（OpenDota constants + Valve CDN 图） | 已有，直接复用 |
| 克制/搭配 | OpenDota `/heroes/{id}/matchups` | P0 接入 |
| 出装热度 | OpenDota `/heroes/{id}/itemPopularity` | P1 接入 |
| 版本强度榜 | 现有 tier list 路径 | 已有，供"推荐导师" |

禁止：抓取 Dotabuff / 任何非 OpenDota 第三方站点；禁止在 UI 上叠灰色遮罩表达"数据缺失/未解锁"。

## 4. 视觉系统 v2 Tokens

### 4.1 色彩（暗色单色；在现有 k3 基础上收敛）

| Token | 值 | 用途 |
|-------|-----|------|
| `base` | `#0B0B0C` | 页面底色 |
| `surface` | `#141416` | 卡片、骨架屏 |
| `elevated` | `#1C1C1F` | 悬浮层、hover 抬升 |
| `input` | `#18181B` | 输入框底 |
| `border-subtle` | `rgba(255,255,255,0.08)` | 全部描边 |
| `text-primary` | `#EDEDEF` | 标题、正文强调 |
| `text-secondary` | `#9B9BA2` | 正文、次级 |
| `text-tertiary` | `#63636B` | 占位、禁用文字 |
| `primary-bg` | `#F5F5F5` | **Primary CTA 底（反白）** |
| `primary-text` | `#0B0B0C` | **Primary CTA 字（反白）** |
| `radiant` | `#7C8F5A` | 仅阵营语义（BP 课件），永不用于 CTA |
| `dire` | `#A65F52` | 仅阵营语义（BP 课件），永不用于 CTA |

**禁用**：`#D8FF3E`（lime）及一切高饱和荧光色；成功/失败不用绿红块，用 `text-primary`/`text-secondary` + 图标表达。

### 4.2 字体与排版

- 正文/UI：Inter（现状保留）；中文回退系统黑体；
- 展示字体：Cinzel 仅用于导师名/称号等"仪式感"位置，正文不用；
- 字号阶梯：`12 / 14(body, 行高22) / 16 / 20(H1)`；导师问候语可用 16–18；
- 数字与胜率用 `font-mono` 或 tabular-nums。

### 4.3 间距 / 圆角 / 阴影

- 间距 8 的倍数：`8/16/24/32/40/48`（沿用现状）；
- 圆角：卡片 `16px`，小元素 `8px`，气泡 `16px`（导师气泡左下角 `4px` 小角，学生气泡右下角小角）；
- 阴影：仅反白 CTA hover 与浮层允许 `0 8px 24px rgba(0,0,0,0.5)`；平面卡片不加阴影，用 `border-subtle` 分层。

### 4.4 导师形象处理

- 立绘来源：Valve CDN（`cdn.cloudflare.steamstatic.com` 竖图/横图，现状已有）；
- S0 卡片：立绘满铺 + 底部渐变（`transparent → base`，属暗色渐隐，**不是灰色遮罩**）上叠中文名/定位/难度；
- S1 头图：竖立绘左置，右侧人格化问候；
- 消息头像：英雄 icon 方形小圆角；
- 已选/禁用态：用 `opacity-40` + 文字标签表达，**禁止盖灰色蒙版**。

### 4.5 动效

- 卡片 hover：`150ms` 抬升至 `elevated` + 反白描边淡入；
- 流式：打字机追加 + `▌` 光标 `1s` 闪烁；不做整段淡入重排；
- 页面切换：导师选定后 `200ms` 立绘从网格位置共享元素过渡到 S1 头图（P1，可用 FLIP；P0 用简单淡入）。

### 4.6 占位态规则（复盘课等）

- 占位卡片：正常卡片样式 + 右上角"敬请期待"标签（`border-subtle` 描边小胶囊），整卡不可点；
- **禁止**：整卡盖灰色半透明层、斜纹、锁图标堆砌。

### 4.7 与 k3 v1 的映射

v2 不新增品牌色，仅做**语义收敛**：`k3-*` 色板全部保留（已满足暗色单色 + 反白 CTA），新增语义别名 `mentor-*`（指向同一色值）用于导师相关组件，避免各组件自行发明颜色。
